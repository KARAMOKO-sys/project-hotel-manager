 # Types d'utilisateurs sur la plateforme PleasantStay

En vous basant sur votre cahier des charges et les personas définis, voici une classification complète des types d'utilisateurs pour votre plateforme.

## 1. Classification par rôles système

### 1.1. Utilisateurs internes (Staff)

#### **Super Administrateur (Super Admin)**
- **Accès**: Toutes les organisations, toutes les propriétés
- **Permissions**:
  - Gestion complète du système
  - Création/modification/suppression d'organisations
  - Gestion des abonnements et facturation
  - Configuration système globale
  - Audit logs complets
  - Support technique niveau 3
- **Interface**: Dashboard d'administration globale

#### **Propriétaire (Owner)**
- **Accès**: Une ou plusieurs propriétés (chaîne hôtelière)
- **Permissions**:
  - Gestion financière complète
  - Configuration des tarifs et promotions
  - Rapports et analytics avancés
  - Gestion des utilisateurs de ses propriétés
  - Signature des contrats et factures
- **Interface**: Dashboard propriétaire multi-propriétés

#### **Gestionnaire Général (General Manager)**
- **Accès**: Une propriété spécifique
- **Permissions**:
  - Supervision opérationnelle quotidienne
  - Gestion du personnel
  - Validation des réservations groupe
  - Approbation des remises exceptionnelles
  - Rapports de performance
- **Interface**: Dashboard management complet

#### **Réceptionniste (Receptionist)**
- **Accès**: Une propriété, module réception
- **Permissions**:
  - Création/modification/annulation réservations
  - Check-in/check-out
  - Gestion des arrivées/départs
  - Attribution des chambres
  - Facturation basique
  - Communication clients
- **Interface**: Interface réception optimisée (rapide, ergonomique)

#### **Comptable (Accountant)**
- **Accès**: Module financier de la propriété
- **Permissions**:
  - Gestion des factures
  - Traitement des paiements
  - Rapprochements bancaires
  - Déclarations fiscales
  - Rapports financiers
- **Interface**: Dashboard comptable

#### **Personnel de Ménage (Housekeeping)**
- **Accès**: Module ménage (mobile/web)
- **Permissions**:
  - Visualisation des tâches assignées
  - Mise à jour des statuts chambres
  - Signalement des problèmes
  - Check-list nettoyage
  - Photos avant/après
- **Interface**: Application mobile simplifiée

#### **Personnel de Maintenance (Maintenance Staff)**
- **Accès**: Module maintenance
- **Permissions**:
  - Visualisation des demandes
  - Intervention sur pannes
  - Signalement des problèmes
  - Gestion des équipements
  - Maintenance préventive
- **Interface**: Application mobile/web

#### **Agent Commercial (Sales Agent)**
- **Accès**: Module commercial
- **Permissions**:
  - Gestion des groupes et événements
  - Devis et contrats
  - Suivi des prospects
  - Négociation tarifs groupes
- **Interface**: Dashboard commercial

#### **Responsable Marketing (Marketing Manager)**
- **Accès**: Module marketing
- **Permissions**:
  - Création campagnes email/SMS
  - Segmentation clients
  - Gestion promotions
  - Analyse des campagnes
  - Réseaux sociaux
- **Interface**: Dashboard marketing

---

### 1.2. Utilisateurs externes (Clients)

#### **Client Voyageur (Guest)**
- **Accès**: Portail client public
- **Permissions**:
  - Consultation disponibilités
  - Réservation en ligne
  - Modification/annulation réservation
  - Demandes spéciales
  - Avis et évaluations
  - Historique des séjours
  - Programme fidélité
- **Interface**: Site web + Application mobile client

#### **Client Professionnel (Corporate Client)**
- **Accès**: Portail entreprise
- **Permissions**:
  - Réservations pour employés
  - Suivi des dépenses
  - Facturation centralisée
  - Rapports d'activité
  - Tarifs négociés
- **Interface**: Dashboard corporate

#### **Agent de Voyage (Travel Agent)**
- **Accès**: Portail agent
- **Permissions**:
  - Réservations commissionnées
  - Tarifs agent
  - Suivi commissions
  - Documentation
- **Interface**: Portail agent dédié

---

### 1.3. Utilisateurs partenaires

#### **Partenaire OTA (OTA Partner)**
- **Accès**: API uniquement
- **Permissions**:
  - Synchronisation disponibilités
  - Envoi/réception réservations
  - Mise à jour tarifs
- **Interface**: API REST

#### **Partenaire Service (Service Partner)**
- **Accès**: Module partenaire
- **Permissions**:
  - Gestion des services (SPA, restaurant, etc.)
  - Consultation réservations services
  - Facturation des services
- **Interface**: Portail partenaire

#### **Intégrateur/Dev (Developer)**
- **Accès**: API publique
- **Permissions**:
  - Accès API (limité par clé)
  - Développement extensions
  - Webhooks
- **Interface**: Documentation API + Console développeur

## 6. Considérations de sécurité

### 6.1. Authentification
- MFA obligatoire pour Super Admin, Owner, Manager
- Session timeout: 30 minutes pour staff, 24h pour guest
- IP whitelisting pour Super Admin (optionnel)

### 6.2. Audit
```sql
CREATE TABLE user_activity_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    action VARCHAR(100) NOT NULL,
    resource_type VARCHAR(50),
    resource_id UUID,
    ip_address INET,
    user_agent TEXT,
    details JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 6.3. Isolation des données
- **Multi-tenancy**: Isolation stricte par `property_id` et `organization_id`
- **Row Level Security**: Chaque requête filtre par les propriétés accessibles

### 3.2. Mode d'inscription client (simple et sécurisé)

#### Étape 1: Inscription minimale
```typescript
// DTO pour inscription client
interface GuestRegistrationDto {
  email: string;
  password?: string; // Optionnel - si fourni, crée un compte complet
  first_name: string;
  last_name: string;
  phone?: string;
  marketing_consent?: boolean;
}

// Workflow d'inscription
async function registerGuest(dto: GuestRegistrationDto) {
  // 1. Vérifier si l'email existe déjà
  const existingGuest = await guestRepository.findOne({
    where: { email: dto.email }
  });

  if (existingGuest) {
    // Si existe, envoyer un code OTP pour connexion
    return sendOtpCode(dto.email);
  }

  // 2. Créer un utilisateur sans mot de passe (guest only)
  const user = await userRepository.create({
    email: dto.email,
    first_name: dto.first_name,
    last_name: dto.last_name,
    phone: dto.phone,
    is_email_verified: false,
    password_hash: dto.password ? await hashPassword(dto.password) : null,
  });

  // 3. Créer le profil guest
  const guest = await guestRepository.create({
    user_id: user.id,
    email: dto.email,
    first_name: dto.first_name,
    last_name: dto.last_name,
    phone: dto.phone,
    marketing_consent: dto.marketing_consent || false,
    data_processing_consent: true,
    consent_granted_at: new Date(),
  });

  // 4. Envoyer email de vérification avec lien magique
  await sendVerificationEmail(dto.email, generateMagicLink());

  return {
    message: "Inscription réussie! Vérifiez votre email.",
    guest_id: guest.id
  };
}
```

#### Étape 2: Connexion sans mot de passe (Magic Link)


### 4.4. Mode d'inscription pour les partenaires

```typescript
// DTO pour inscription partenaire
interface PartnerRegistrationDto {
  // Informations personnelles
  email: string;
  password: string;
  first_name: string;
  last_name: string;
  phone: string;

  // Informations société
  company_name: string;
  company_registration?: string;
  tax_id?: string;
  partner_type: string; // 'real_estate_agency', 'property_owner', etc.

  // Contact
  contact_name?: string;
  contact_phone?: string;
  contact_email?: string;

  // Documents
  registration_document?: File; // À uploader
  tax_document?: File;

  // Acceptation des conditions
  terms_accepted: boolean;
  data_processing_accepted: boolean;
}

// Workflow d'inscription partenaire
async function registerPartner(dto: PartnerRegistrationDto) {
  // 1. Vérifier que l'email n'existe pas
  const existingUser = await userRepository.findOne({
    where: { email: dto.email }
  });

  if (existingUser) {
    throw new Error('Email déjà utilisé');
  }

  // 2. Créer l'utilisateur
  const user = await userRepository.create({
    email: dto.email,
    password_hash: await hashPassword(dto.password),
    first_name: dto.first_name,
    last_name: dto.last_name,
    phone: dto.phone,
    is_email_verified: false,
    is_active: true,
  });

  // 3. Upload des documents
  const registrationDocUrl = await uploadDocument(dto.registration_document);
  const taxDocUrl = await uploadDocument(dto.tax_document);

  // 4. Créer le profil partenaire
  const partner = await partnerRepository.create({
    user_id: user.id,
    company_name: dto.company_name,
    company_registration: dto.company_registration,
    tax_id: dto.tax_id,
    partner_type: dto.partner_type,
    contact_name: dto.contact_name || `${dto.first_name} ${dto.last_name}`,
    contact_phone: dto.contact_phone || dto.phone,
    contact_email: dto.contact_email || dto.email,
    registration_document_url: registrationDocUrl,
    tax_document_url: taxDocUrl,
    status: 'pending', // En attente de validation admin
    metadata: {
      terms_accepted_at: new Date(),
      terms_version: '1.0',
      ip_address: getClientIp(),
    }
  });

  // 5. Envoyer email de confirmation
  await sendPartnerConfirmationEmail(dto.email, {
    partner_id: partner.id,
    company_name: dto.company_name
  });

  // 6. Notifier les admins pour validation
  await notifyAdminsForPartnerApproval(partner.id);

  return {
    message: "Inscription partenaire soumise avec succès! En attente de validation.",
    partner_id: partner.id,
    status: 'pending'
  };
}
```

## 6. Résumé des attributs par type d'utilisateur

| Type | Table | Attributs spécifiques | Mode d'inscription |
|------|-------|----------------------|-------------------|
| **Super Admin** | `super_admins` | access_level, department, alert_email | Création interne par équipe technique |
| **Owner** | `owners` | company_name, tax_id, contract, subscription | Inscription avec validation admin |
| **Receptionist** | `receptionists` | employee_code, shift_schedule, max_discount | Création par Owner/Manager |
| **Housekeeping** | `housekeeping_staff` | employee_code, specialization, working_days | Création par Manager |
| **Accountant** | `accountants` | certification, approval_limit | Création par Owner |
| **Guest** | `guests` | loyalty_points, preferences, consentements | Magic link / OTP / Email |
| **Partner** | `partners` | company_name, partner_type, commission_rate | Inscription + validation admin + documents légaux |

Cette structure permet une gestion flexible et sécurisée de tous les types d'utilisateurs avec des workflows d'inscription adaptés à chaque cas d'usage.
